## Theory

Chomsky Normal Form is a standardized form of context-free grammars where every production rule strictly follows one of two formats: either a non-terminal producing exactly two non-terminals (A → BC) or a non-terminal producing a single terminal symbol (A → a). Optionally, the grammar may include the rule S → ε if the language includes the empty string. The main purpose of CNF is to simplify the structure of grammars, making them easier to analyze and process using algorithmic techniques such as the CYK (Cocke–Younger–Kasami) parsing algorithm. By restricting the form of productions, CNF enables uniform treatment of parsing problems and helps in formal proofs related to computational linguistics and automata theory.

Converting a context-free grammar to Chomsky Normal Form involves a systematic series of steps: removing null (ε) productions, eliminating unit productions (rules where a non-terminal produces another single non-terminal), and eliminating useless symbols. After cleanup, complex productions with more than two non-terminals or a mix of terminals and non-terminals are broken down into binary rules by introducing new non-terminal variables. This process preserves the language generated by the original grammar (except for possible omission of ε if not handled explicitly), and results in an equivalent CNF grammar. The conversion ensures that the final grammar is suitable for efficient parsing and formal manipulation.

CNF is essential in theoretical computer science, particularly in formal language processing, compiler design, and natural language parsing. It plays a crucial role in algorithms that verify whether a string belongs to the language of a grammar, especially the CYK algorithm, which only works efficiently with CNF grammars. Moreover, CNF provides a foundation for proving properties about context-free languages, such as closure under certain operations or decidability of language problems. By reducing arbitrary grammars to a fixed structure, CNF also facilitates the design of parsers and the study of ambiguity and complexity in context-free grammars.

## Implementation description

This code eliminates ε-productions by first removing explicit "ε" from all production sets. Then, it creates new productions by examining each existing production and generating variations that exclude nullable symbols. Fully nullable symbols are removed entirely, while other nullable symbols are considered optional via bitmask combinations. The result is a set of new productions for each non-terminal that preserves the original language without relying on ε-productions. This step is crucial in converting a grammar to Chomsky Normal Form by ensuring all rules are free from nullable derivations.
```c++
for (auto &[nt, prods]: productions) prods.erase("ε");

map<string, set<string>> newProductions;
for (const auto &[nt, prods]: productions) {
    for (const string &prod: prods) {
        vector<string> parts = tokenize(prod), filtered;
        for (const string &p: parts)
            if (!fullyNullable.count(p)) filtered.push_back(p);
        if (filtered.empty()) continue;
        int total = 1 << filtered.size();
        for (int mask = 0; mask < total; ++mask) {
            vector<string> newParts;
            for (int i = 0; i < filtered.size(); ++i)
                if (!(mask & (1 << i)) || !nullable.count(filtered[i]))
                    newParts.push_back(filtered[i]);
            if (!newParts.empty())
                newProductions[nt].insert(join(newParts, ""));
        }
    }
}
```

This function removes unit productions, which are rules where one non-terminal maps directly to another non-terminal (e.g., A → B). It first identifies all such unit productions for each non-terminal by checking if the production is a known non-terminal. Then, for each identified unit production, it replaces it with the set of productions of the target non-terminal. This ensures that the grammar directly maps non-terminals to meaningful right-hand sides, not through intermediaries. The original unit production is removed afterward, cleaning up the grammar structure in preparation for CNF conversion.
```c++
void eliminateUnitProductions() {
    for (auto &nonTerminal: nonTerminals) {
        set<string> unitProductions;
        for (auto &prod: productions[nonTerminal])
            if (nonTerminals.count(prod)) unitProductions.insert(prod);
        for (auto &unit: unitProductions) {
            for (auto &unitProd: productions[unit])
                productions[nonTerminal].insert(unitProd);
            productions[nonTerminal].erase(unit);
        }
    }
}
```

This code snippet creates unique non-terminal symbols to represent each terminal in the grammar, which is required for converting to Chomsky Normal Form (CNF). In CNF, every production of the form A → BC must consist of non-terminals only, so terminals appearing in longer productions (e.g., A → aB or A → Ba) need to be replaced. To handle this, the code iterates over all terminals and assigns each a corresponding new non-terminal (e.g., a becomes T_a). These new non-terminals are then stored in a map (terminalToNonTerminal) so that they can be easily substituted in other productions later. Finally, the new non-terminals are added to the nonTerminals set, ensuring they are treated like valid non-terminal symbols throughout the grammar.

This code processes production rules to ensure they conform to Chomsky Normal Form. If a production has a single terminal (e.g., A → a), it replaces it with a mapped non-terminal (e.g., A → T_a). If it's a single non-terminal (A → B), it's kept as is and later handled in unit production elimination. For mixed or long productions, terminal symbols are first replaced with their corresponding non-terminals. If the right-hand side has exactly two symbols (e.g., A → BC), it’s directly valid in CNF. For longer sequences (e.g., A → BCD), the rule is broken down by introducing new non-terminals (e.g., A → B X1, X1 → C D), ensuring all resulting rules are binary.
